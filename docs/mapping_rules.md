# 입력 변수 매핑 규칙 및 데이터 정제 기준 (3~4주차)

> 작성: 이소흔 · 수원도시공사 운행내역(2024.12~2026.08, 337,974건, 14개 항목) 기준

## 성과지표 재정의
받은 데이터에 **배차일시가 없어** 계획서의 '배차 대기시간(배차−접수)'은 계산할 수 없음
→ 이용자가 실제로 기다린 **접수~승차 시간(승차일시 − 접수일시)**을 핵심 성과지표로 설정

## 매핑 규칙
| 모형 입력값 | 원본 항목 | 매핑 규칙 |
|---|---|---|
| 지역 i | 출발지 X·Y 좌표 | QGIS 500m 격자와 공간 조인해 격자 ID 부여 |
| 시간 구간 t | 접수일시 | 1시간 단위, 평일/주말 구분 |
| 수요 d(i,t) | 예약콜, 결과 | 즉시콜만 집계, 고객 취소도 수요로 포함 |
| 빈 차 위치·시점 | 차량번호, 하차일시, 목적지 좌표 | 하차 직후 해당 격자에서 빈 차 발생으로 간주 |
| 대기시간 W (성과지표) | 접수일시, 승차일시 | 승차 − 접수(분), 즉시콜 중 하차 건 |
| 배차 성공률 (성과지표) | 결과 | 하차 건 ÷ 즉시콜 접수 건 |
| 운전원 근무 제약 | 결과 = '(센)퇴근휴게침범' | 발생 시간대로 시간대별 가용 차량 상한 추정 |
| 차량–이용자 적합성 | 휠체어 | 리프트 필요 여부로 변환 (차량 제원 추가 요청) |

## 정제 기준
- 승차일시가 접수일시보다 앞선 14건 제외 (기입 오류)
- 승차~하차 시간이 음수이거나 비정상적으로 긴 건 제외
- 출발지가 수원시 밖인 약 0.8%는 수요 집계에서 제외 (관외 목적지는 차량 점유 요인이라 유지)
- 날짜 기준은 '일자'가 아닌 접수일시로 통일
- 예약콜(4.5%)은 하루 전 접수로 대기 개념이 달라 분리
